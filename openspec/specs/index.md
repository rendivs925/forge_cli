# Specification Catalog

Each spec domain owns the requirement prefixes declared in this catalog. The
catalog is navigation, not a second registry.

| Domain | Capability root | Purpose |
|---|---|---|
| Architecture | `architecture/` | Forge constitution: integration over reimplementation, core independence |
| CLI | `cli/` | Command surface, machine-readable output, exit codes, agent interface |
| Configuration | `configuration/` | Layered configuration, provenance, validation, versioning |
| Analysis | `analysis/` | Engine orchestration, analyzer contract, execution |
| Findings | `findings/` | Unified finding model and identity |
| Rules | `rules/` | Rule identity, metadata, packs, declarative rules, testing |
| Plugins | `plugins/` | Stable extension mechanisms and process isolation |
| Policies | `policies/` | Composable organization and repository policies |
| Quality gates | `quality-gates/` | Policy evaluation and enforcement |
| Baseline | `baseline/` | Existing technical debt management |
| Reporting | `reporting/` | Reporter model and reproducibility |
| Caching | `caching/` | Incremental analysis and cache correctness |
| Project rules | `project-rules/` | Repository-local and organization rules |
| Tools | `tools/` | External tool discovery, health, and versions |
